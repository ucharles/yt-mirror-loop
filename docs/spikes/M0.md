Environment: Xcode 27.0, iOS 27.0 simulator (iPad Pro 13", headless — Xcode 27 has no Simulator.app), Expo SDK 57 / RN 0.86 (New Architecture).

## Other findings

- **Maven Central is throttled on this network**; `scripts/lib.sh` exports `ENTERPRISE_REPOSITORY` (Google's Maven mirror) for `pod install`.
- **Custom-scheme deep links** (`ytmirror://e2e/...`) trigger an "Open in yt-mirror-loop?" system alert on iOS 27 that Maestro cannot drive. E2E builds (`EXPO_PUBLIC_E2E=1`) render a tiny command field (`e2e-cmd`) that runs the same commands; the deep-link route still exists for manual use.
- **Hardware keyboard (E-20)**: Maestro cannot send hardware keys on iOS, so E-20 is an XCUITest (`modules/mirror-player/ios/KeyboardE2E`) using `XCUIElement.typeKey`, run by `scripts/e2e-ios.sh`.
- **E2E build flavour**: Release configuration with the JS bundle embedded and `EXPO_PUBLIC_E2E=1` (no Metro needed). Debug-only hooks are compiled out of the normal Release/IPA build.
- The E-04 flow plays at 0.25× so Maestro's polling can observe the 2 s mirrored window; precision is asserted from the engine's transition log (≤ 34 ms), not from polling.
