# Test Plan — yt-mirror-loop

> Companion to [`PRD.md`](./PRD.md) and [`IMPLEMENTATION_PLAN.md`](./IMPLEMENTATION_PLAN.md).
> **Rule: tests in this document are written (and fail) before the feature code they cover.** A milestone is done only when every test in its scope passes.

---

## 1. Test layers and tools

| Layer | Tool | Runs on | What it covers |
|---|---|---|---|
| **L1 Unit (TS)** | Jest (`jest-expo` preset) | Node | Pure domain logic: URL parsing, segment math, XOR mirror state, A-B loop, zod schemas, migration, import/export, conflict resolution, file reconciliation |
| **L2 Unit (player JS)** | Jest + `jsdom` + fake timers / fake rAF | Node | The JS that runs *inside* the YouTube WebView (clock interpolation, segment judgement, CSS toggle, loop). Written as a TS module and bundled into the HTML, so it is testable without a WebView |
| **L3 Component** | Jest + `@testing-library/react-native` | Node | Screens and components with mocked native modules (`MirrorPlayer`, MMKV, document picker, file system, clipboard, WebView) |
| **L4 Native unit** | XCTest (Swift, in `modules/mirror-player/ios/Tests`) | iPad simulator | `MirrorPlayer` module: boundary-time computation, mirror transform, exact seek, frame step, A-B loop, pitch algorithm, external-display scene handling |
| **L5 E2E** | **Maestro** | **iPadOS simulator** (iPad Pro 13" / iPad Air 11", iPadOS 18+) | Full user flows on a debug build of the real app |
| **L6 Manual (device-only)** | Checklist | Real iPad + Apple TV | Things a simulator cannot prove: real AirPlay screen mirroring, SideStore re-signing, 14-day survival, 1 GB import on device |

Why Maestro over Detox: works with Expo prebuild without patching the native test runner, YAML flows are easy to keep next to features, supports iPad simulators, `addMedia`, deep links and screenshots.

### Test hooks the app must provide (debug builds only, `__DEV__` / `E2E=1`)
These are part of the test plan so feature code is designed to be observable:

1. **testIDs / accessibility labels** on every control listed in PRD §3 (e.g. `btn-play`, `btn-mark-start`, `badge-mirror` with label `mirror:on|off`, `segment-row-<i>`).
2. **Debug deep links** (`ytmirror://e2e/...`), compiled out of Release:
   - `e2e/reset` — wipe MMKV + `Documents/videos/`.
   - `e2e/import-fixture?name=<file>` — run the real import pipeline on a file bundled in the debug app (bypasses the system document picker, which Maestro cannot drive reliably).
   - `e2e/import-json?name=<file>` — same for export JSON fixtures.
   - `e2e/seek?t=<sec>` — deterministic seek.
3. **Mirror transition log** — engine emits `{expectedAt, actualAt, mediaTime, state}` for every flip; a hidden debug panel (`panel-e2e-log`) renders the last N entries and the max error, so E2E can assert precision.
4. **Fake external display** — debug-only toggle that routes the "external" window into an in-app overlay, plus native tests using a fake `UIScreen`/scene. Real AirPlay remains L6.

## 9. Gate — "all tests must pass"

`npm run test:all` must exit 0 before a milestone is closed and before every commit to `main`:

```
npm run lint && npm run typecheck      # eslint + tsc --noEmit
npm run test -- --coverage             # L1–L3 (Jest), coverage thresholds enforced
npm run test:native                    # L4 XCTest on iPad simulator
npm run e2e:ios                        # L5 Maestro, tag=offline (network tag when online)
```

A test may never be skipped/`.only`'d to make the gate green (ESLint rule `jest/no-disabled-tests`, `jest/no-focused-tests`; CI grep for `skip:` in Maestro flows). Flaky tests are fixed or quarantined with an issue link, never silently retried more than once.
