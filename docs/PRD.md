# PRD — yt-mirror-loop

> iPad용 안무 연습 플레이어. 유튜브 영상이나 로컬 영상 파일에서 지정한 구간을 자동으로 좌우 반전하고, AirPlay로 TV에 반전 영상을 띄운다.

| 항목 | 내용 |
|---|---|
| 상태 | Draft v0.2 (2026-09-27) — 로컬 영상 가져오기 추가 |
| 작성자 | JungHyun Yoo |
| 대상 사용자 | 본인 포함 최대 2명 (비공개, 앱스토어 배포 없음) |
| 플랫폼 | iPadOS 18+ (최소 지원 17), 가로/세로 |
| 기술 스택 | React Native (Expo, prebuild) + 커스텀 Swift 네이티브 모듈 |

---

## 1. 배경과 목표

안무 영상을 따라 할 때는 영상이 거울처럼 보여야 따라 하기 쉽다. 그런데 필요한 반전은 영상 전체가 아니라 **특정 구간**(예: 댄서가 뒤돌아서는 파트)인 경우가 많다. 유튜브 기본 플레이어에는 반전 기능이 없고, 매번 수동으로 전환하면 연습 흐름이 끊긴다.

**목표**
1. 유튜브 URL을 붙여넣으면 바로 재생되고, 지정한 구간에서 자동으로 좌우 반전된다.
2. 기기에 있는 영상 파일(mp4/mov)도 가져와 같은 방식으로 연습할 수 있고, 이 경우 프레임 단위로 정밀하게 제어된다.
3. 구간 설정이 영상별로 로컬에 저장되고, 파일로 내보내고 가져올 수 있다.
4. AirPlay로 TV에 연결하면 TV에는 반전이 적용된 영상만 전체화면으로 나오고, iPad는 컨트롤러가 된다.
5. 비용 없이(무료 Apple ID) 두 대의 iPad에 설치해 계속 쓸 수 있다.

**비목표 (Non-goals)**
- **앱 안에서 영상 다운로드**(yt-dlp 등 내장). 앱은 파일이 어디서 왔는지 관여하지 않고, 사용자가 이미 가진 파일을 가져오는 기능만 제공한다.
- 유튜브 영상의 오프라인 재생
- 역재생(시간 반전), 상하 반전 (로컬 영상의 역재생은 추후 검토)
- 앱스토어/TestFlight 배포, iPhone 최적화
- 클라우드 동기화, 계정
- 영상 파일 자체를 내보내거나 기기 간 전송하는 기능 (JSON에는 구간 데이터만 들어감)
- 구간별 반복 횟수, 루프 사이 카운트다운 (추후 검토)

## 2. 핵심 개념

| 용어 | 정의 |
|---|---|
| **소스 (Source)** | 영상의 출처. `youtube`(IFrame 재생) 또는 `local`(앱 샌드박스에 복사된 파일을 AVPlayer로 재생) |
| **반전 구간 (Mirror Segment)** | `[start, end)` 시간 범위. 재생 위치가 이 범위 안에 있으면 반전 상태가 뒤집힌다. 영상별로 저장한다. |
| **전체 반전 (Base Mirror)** | 영상 단위 토글. 구간 밖의 기본 반전 상태를 정한다. |
| **최종 반전 상태** | `baseMirror XOR inAnySegment`. 예를 들어 전체 반전이 ON이면 구간 안에서는 원본으로 보인다. |
| **A-B 루프** | 연습 중에 임시로 쓰는 반복 범위. **저장하지 않으며** 반전 구간과 무관하다. |
| **플레이어 엔진** | 소스별 재생 구현. `YouTubeEngine`(WebView)과 `NativeEngine`(AVPlayer)이 같은 `PlayerBridge` 인터페이스를 구현하므로, UI와 구간·루프 로직은 소스와 무관하게 동작한다. |

## 3. 기능 요구사항

### 3.1 유튜브 영상 추가 (P0)
- URL 입력란에 붙여넣으면 videoId를 파싱한다. 클립보드에 유튜브 URL이 있으면 붙여넣기를 제안한다.
- 지원 형식: `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`, `youtube.com/embed/`, `m.youtube.com`, `music.youtube.com`. `t=`/`start=` 파라미터가 있으면 초기 위치로 쓴다. `list=`는 무시한다.
- 제목과 썸네일은 oEmbed(`https://www.youtube.com/oembed?url=...&format=json`)로 가져온다. API 키는 쓰지 않는다. 가져오지 못하면 videoId를 제목으로 쓴다.
- 이미 등록된 videoId를 추가하면 기존 항목을 열지, 새 항목으로 추가할지 묻는다.

### 3.2 로컬 영상 가져오기 (P0)
- **진입 경로**
  - (P0) 라이브러리의 [파일에서 가져오기]: `expo-document-picker`로 파일을 연다. 형식은 `public.movie`, 여러 개를 한 번에 고를 수 있다.
  - (P1) [사진 보관함에서 가져오기]: 직접 찍은 연습 영상을 가져온다.
  - (P2) 파일 앱이나 AirDrop의 "다음으로 열기 → yt-mirror-loop"으로 가져온다(문서 타입 등록).
- **저장**: 고른 파일을 앱 샌드박스 `Documents/videos/<uuid>.<ext>`로 **복사**한다. 원본 위치(iCloud Drive 등)에 의존하지 않기 위해서다. 복사 중에는 진행률을 보여 주고 취소할 수 있다. iCloud에만 있는 파일은 문서 선택기가 먼저 내려받는다.
- **메타데이터**: 제목의 기본값은 파일명(확장자 제외)이다. 길이, 해상도, 파일 크기를 AVAsset에서 읽는다. 썸네일은 10% 지점 프레임으로 만든다(`expo-video-thumbnails`).
- **지원 포맷**: AVFoundation이 재생할 수 있는 컨테이너/코덱(mp4·mov·m4v, H.264·HEVC, AAC). 재생할 수 없는 파일(webm/VP9/AV1-in-mkv 등)은 가져올 때 거부하고 "iPad에서 재생할 수 없는 형식입니다(mp4/H.264 권장)"라고 안내한다.
- **유튜브 연결 (선택)**: 로컬 영상에 원본 유튜브 URL을 선택적으로 연결할 수 있다. 연결해 두면 제목과 썸네일을 oEmbed로 가져오고, 내보내기/가져오기 때 상대 기기의 같은 videoId 항목과 매칭할 수 있다.
- **저장공간**: 설정 화면에 로컬 영상 총용량을 표시한다. 라이브러리에서 로컬 영상을 삭제하면 파일도 함께 지운다.
- iOS 백업에서 제외할지는 사용자 설정으로 둔다. 기본값은 제외(`isExcludedFromBackup`)로, 용량이 큰 파일이 iCloud 백업을 채우지 않게 한다.

### 3.3 플레이어 공통 (P0)
- 컨트롤: 재생/일시정지, 타임라인 스크럽, 미세 탐색(±0.1초, ±1초, ±5초), 재생 속도.
- 타임라인 위에 반전 구간을 색 띠로 표시하고, A-B 루프 범위도 별도 색으로 표시한다.
- 현재 반전 상태를 명확히 표시한다(아이콘/배지).
- 재생 중에는 화면이 꺼지지 않게 한다(`expo-keep-awake`).
- 영상별 마지막 재생 속도와 마지막 재생 위치를 기억한다.

### 3.4 유튜브 엔진 (P0)
- YouTube IFrame Player API를 `react-native-webview` 안에서 실행한다.
- 재생 속도는 `getAvailablePlaybackRates()` 범위(보통 0.25–2배)를 쓴다.
- 임베드가 금지된 영상(에러 101/150)은 "이 영상은 외부 재생이 차단되어 있습니다"라고 안내한다. 가능하면 "파일로 가져오기" 경로도 함께 안내한다.

### 3.5 네이티브 엔진 — 로컬 영상 (P0)
- 커스텀 Swift 모듈이 `AVPlayer`를 소유하고, RN에는 `AVPlayerLayer`를 담은 네이티브 뷰(`<MirrorPlayerView>`)를 노출한다.
- **반전**: 플레이어 레이어에 `CATransform3DMakeScale(-1, 1, 1)`를 적용한다. 암묵적 애니메이션은 끈다.
- **구간 경계**: `addBoundaryTimeObserver`에 모든 구간의 start/end를 등록해 **네이티브에서 직접** 전환한다. 브리지 지연 없이 프레임 수준으로 맞춘다. 구간이 바뀌면 옵저버를 다시 등록한다. 탐색 직후에는 현재 시각으로 상태를 다시 계산한다.
- **탐색**: `seek(to:toleranceBefore:.zero, toleranceAfter:.zero)`로 정확히 이동한다. 미세 탐색에 프레임 단위(±1프레임, `AVPlayerItem.step(byCount:)`)를 추가한다.
- **속도**: 0.25–2배(0.05 단위 슬라이더 + 프리셋). 속도를 바꿔도 음정이 유지되도록 `audioTimePitchAlgorithm = .timeDomain`(또는 `.spectral`)을 쓴다.
- **A-B 루프**: B 지점에 경계 옵저버를 걸고, 도달하면 A로 정확히 탐색한다. 끊김을 줄이려고 A 지점을 미리 탐색해 두는 최적화를 고려한다.
- 현재 시각, 재생 상태, 길이는 이벤트로 RN에 알린다(UI 갱신용, 약 10Hz).

### 3.6 반전 구간 편집 (P0)
- 재생 중에 **[시작 마크]**를 누르면 현재 시각이 start가 되고, **[끝 마크]**를 누르면 end가 된 뒤 구간이 생성된다.
- 구간 목록에서 각 구간의 start/end를 ±0.1초, ±1초로 미세 조정한다. 로컬 영상은 ±1프레임도 조정할 수 있다. 조정할 때 해당 지점으로 탐색해 미리보기를 보여 준다.
- 구간마다 선택적으로 라벨을 붙인다(예: "뒤돌기 1").
- 구간을 삭제하고, 탭하면 해당 start로 이동한다.
- 검증 규칙: `start < end`, 최소 길이 0.2초, 영상 길이를 넘을 수 없음. **겹치는 구간은 저장할 때 자동으로 병합한다**(XOR 모델에서 겹침이 생기면 동작이 모호해지기 때문).
- 전체 반전 토글은 영상별로 저장한다.

### 3.7 유튜브 엔진의 반전 전환 정밀도 (P0)
- 목표: 구간 경계 대비 전환 오차 **≤ 100ms** (1배속 기준). 로컬 영상은 3.5에 따라 프레임 수준으로 맞춘다.
- 구현 원칙: 구간 판정 로직을 **WebView 내부 JS에서** 실행해 RN 브리지 왕복을 없앤다.
  - `getCurrentTime()` 샘플을 받은 뒤로는 `requestAnimationFrame`으로 `lastSample + elapsed × playbackRate`를 보간해 현재 시각을 추정한다.
  - 판정 결과가 바뀌면 컨테이너의 CSS `transform: scaleX(-1)`를 즉시 토글한다.
  - RN은 구간 목록과 baseMirror 값만 WebView로 보낸다(`postMessage`).
- 탐색, 속도 변경, 버퍼링 상태로 바뀌면 보간 값을 버리고 즉시 다시 샘플링한다.

### 3.8 A-B 루프 (P0)
- **[A]**/**[B]** 마크 버튼으로 현재 시각을 지정하고, ±0.1초로 미세 조정한다.
- 재생 위치가 B에 도달하면 A로 이동한다. 판정은 엔진 내부(WebView JS 또는 네이티브 경계 옵저버)에서 한다.
- 루프 ON/OFF 토글과 초기화 기능을 둔다. 저장하지 않으므로 앱을 다시 시작하거나 다른 영상을 열면 초기화된다.

### 3.9 라이브러리 (P0 / P1)
- (P0) 영상 목록을 썸네일, 제목, 구간 개수, **소스 배지**(YouTube / 파일)와 함께 보여 준다.
- (P0) 제목 수정(원제는 별도 보관), 메모.
- (P1) 검색(제목/메모/태그), 정렬(최근 사용순/추가순/이름순), 소스 필터.
- (P1) **태그**: 영상 하나에 여러 태그를 달고 태그로 필터링한다. 폴더 대신 태그를 쓴다. 두 개념을 모두 두는 것은 사용자 2명 규모에 비해 과하다.
- (P0) 영상 삭제(확인 필요, 로컬 영상은 "파일도 삭제됨" 명시).
- (P0) 로컬 영상의 파일이 사라졌거나 가져오기로 들어와 파일이 없는 경우에는 "파일 없음" 상태로 표시하고 [파일 연결]로 다시 연결할 수 있게 한다.

### 3.10 저장 (P0)
- 모든 데이터는 기기 로컬에만 저장한다. 메타데이터 저장소는 `react-native-mmkv`를 쓰고, 스키마 버전 필드를 두어 이후 마이그레이션에 대비한다.
- 로컬 영상 파일은 `Documents/videos/`에 보관한다. 경로는 절대경로가 아니라 **파일명만** 저장한다(앱을 재설치하거나 다시 서명하면 컨테이너 경로가 바뀔 수 있음).
- 변경할 때마다 즉시 저장한다. 별도 저장 버튼은 두지 않는다.
- 앱을 시작할 때 저장된 파일명과 실제 파일을 대조해 고아 파일과 누락 파일을 정리하거나 표시한다.

### 3.11 내보내기 / 가져오기 (P0)
- **내보내기**: 전체 또는 선택한 영상을 JSON 파일(`yt-mirror-loop-YYYYMMDD.json`)로 만들어 iOS 공유 시트로 보낸다(AirDrop, 파일 앱 등). **영상 파일은 포함하지 않는다.**
- **가져오기**: 문서 선택기(`expo-document-picker`)로 JSON 파일을 연다. 파일 앱에서 "다음으로 열기"로 여는 것은 P2다.
- 스키마 검증(zod)에 실패하면 가져오지 않고 오류 메시지를 보여 준다.
- **충돌 판정 키**
  - `youtube` 항목: `videoId`
  - `local` 항목: `linkedVideoId`가 있으면 그것, 없으면 `fingerprint`(파일 크기 + 길이(ms))
- **충돌 처리**: 같은 키가 이미 있으면 영상별로 **덮어쓰기 / 건너뛰기 / 복사본으로 추가** 중에서 고르게 한다. "나머지 모두에 적용" 체크박스를 둔다. 덮어써도 기존 로컬 파일 연결은 유지하고 구간 데이터만 바꾼다.
- **매칭되지 않은 로컬 항목**: "파일 없음" 상태로 추가한다. 사용자가 [파일 연결]로 파일을 고르면, 길이가 ±0.5초 안에서 일치할 때 바로 연결하고 불일치하면 경고한 뒤 사용자가 확인해야 연결한다.

### 3.12 AirPlay / 외부 디스플레이 (P0)
- 사용자가 제어 센터에서 **화면 미러링**으로 Apple TV나 AirPlay 수신기에 연결하면, 앱이 외부 디스플레이를 감지해 외부 모드로 바뀐다.
  - **TV**: 반전 로직이 적용된 영상만 전체화면(검은 배경, UI 없음)으로 띄운다.
  - **iPad**: 컨트롤러 화면(타임라인, 구간, A-B 루프, 속도, 반전 상태 표시)으로 바뀐다.
- **소스별 차이**

  | | 유튜브 | 로컬 |
  |---|---|---|
  | TV 렌더링 | 외부 윈도우의 네이티브 `WKWebView`(같은 플레이어 HTML/JS) | 외부 윈도우의 `AVPlayerLayer` |
  | iPad 미리보기 | 없음 (플레이어가 두 개면 동기화 문제) | **있음** — 같은 `AVPlayer`에 레이어를 하나 더 붙이므로 자동으로 동기화됨 |

- 연결이 끊기면 재생 위치와 상태를 유지한 채 iPad 단독 모드로 돌아간다.
- 오디오는 화면 미러링 경로로 TV에 나간다.
- 일반 AirPlay *영상 전송*은 반전이 적용되지 않으므로 끈다. 유튜브는 IFrame의 AirPlay 버튼을 비활성화하거나 안내 문구를 표시한다. 로컬은 `AVPlayer.allowsExternalPlayback = false`로 설정해 화면 미러링 경로만 쓰게 한다.
- 구현: 커스텀 Expo Module(Swift)을 만든다.
  - `UIWindowSceneSessionRoleExternalDisplayNonInteractive` 역할의 씬을 받아 외부 화면에 윈도우를 만든다.
  - 현재 소스에 따라 WKWebView 또는 AVPlayerLayer를 올린다.
  - RN ↔ 네이티브 모듈 사이의 명령/이벤트 인터페이스는 `PlayerBridge`로 추상화한다.

### 3.13 키보드 단축키 (P2)
- 외장 키보드를 쓸 때: Space(재생/정지), ←/→(±1초), Shift+←/→(±0.1초), `,`/`.`(로컬 ±1프레임), `[`/`]`(A/B 마크), M(전체 반전).

## 6. 기술 설계 요약

| 영역 | 선택 |
|---|---|
| 프레임워크 | Expo (최신 SDK, New Architecture), `expo prebuild` 후 로컬 Xcode 빌드 |
| 유튜브 엔진 | `react-native-webview` + 자체 작성 HTML(IFrame API). 반전/루프 로직은 HTML 안의 JS |
| 네이티브 엔진 | 커스텀 Expo Module `MirrorPlayer`(Swift): `AVPlayer` 소유, `<MirrorPlayerView>` 노출, 경계 옵저버로 반전/루프 처리 |
| 외부 디스플레이 | 같은 Expo Module 안에 UIScene 기반 외부 윈도우. 로컬은 AVPlayerLayer, 유튜브는 WKWebView |
| 저장 | `react-native-mmkv` + zod 스키마. 영상 파일은 `expo-file-system`으로 `Documents/videos/`에 저장 |
| 상태 관리 | zustand |
| 파일 | `expo-sharing`, `expo-document-picker`, `expo-file-system`, `expo-video-thumbnails` |
| 기타 | `expo-keep-awake`, `expo-clipboard`, (P1) `expo-image-picker`(사진 보관함) |

**`expo-video`를 쓰지 않는 이유**: 외부 디스플레이에 같은 `AVPlayer` 인스턴스를 공유하고, 레이어 transform과 경계 옵저버를 직접 제어해야 한다. 그래서 플레이어를 자체 모듈이 소유하는 편이 단순하다.

**WebView 임베드 주의**: 로컬 HTML을 `baseUrl` 없이 로드하면 Referer/origin이 비어 유튜브가 재생을 거부할 수 있다(에러 152/153 계열). HTML은 `baseUrl`을 유효한 https origin으로 지정해 로드하고, IFrame `origin` 파라미터를 같은 값으로 맞춘다. **M0 스파이크에서 가장 먼저 검증한다.**

## 7. 배포 (무료, 앱스토어/TestFlight 없음)

TestFlight를 쓰려면 Apple Developer Program($99/년)에 가입해야 하므로 제외한다. 무료 Apple ID로 서명하면 **앱이 7일마다 만료**되고, 계정당 활성 앱은 3개로 제한된다. 이 만료를 자동 갱신으로 해결한다.

### 7.1 권장: SideStore (기기 단독 갱신)
- **최초 1회(Mac 필요)**: 페어링 파일을 만들고 SideStore를 설치한다. 이후에는 iPad 안의 로컬 VPN 앱(LocalDevVPN 계열)을 통해 컴퓨터 없이 재서명할 수 있다.
- **자동화**: iOS 단축어 앱의 **개인용 자동화**(예: 매일 새벽 4시, 또는 충전기에 연결될 때)로 SideStore의 "모든 앱 갱신" 액션을 실행한다.
- **사용자 2명**: 각자 본인 Apple ID로 SideStore에 로그인해 같은 IPA를 서명한다. IPA는 AirDrop이나 파일 앱으로 전달한다.
- **로컬 영상 보존 확인 필요**: 같은 번들 ID로 다시 서명(갱신/업데이트)해도 앱 컨테이너의 `Documents/`가 유지되는지 확인한다. 앱을 삭제 후 재설치하면 영상이 사라지므로, 사용자 안내에 명시한다.

### 7.2 대안: AltStore Classic + AltServer
- Mac에서 AltServer를 상시 실행하고 iPad가 같은 Wi-Fi에 있으면 백그라운드로 자동 갱신된다. Mac이 늘 켜져 있어야 한다는 제약이 있다.

### 7.3 최후 수단: Xcode 직접 설치
- 개발 중에는 이 방식이 기본이다. 7일마다 Mac에 연결해 다시 빌드해야 한다.

### 7.4 IPA 빌드 절차
1. `npx expo prebuild -p ios`
2. `xcodebuild archive -workspace ... -scheme ... -configuration Release CODE_SIGNING_ALLOWED=NO`
3. `.app`을 `Payload/`로 감싸 `yt-mirror-loop.ipa`로 압축한다. SideStore/AltStore가 설치할 때 재서명한다.
4. 이 과정을 `scripts/build-ipa.sh`로 스크립트화한다.

> 스파이크 검증 항목: 무료 계정으로 서명할 때 외부 디스플레이 씬 구성에 필요한 권한(entitlement) 문제가 없는지 확인한다(추가 entitlement는 필요 없을 것으로 예상).

## 9. 수용 기준 (주요)

**유튜브**
- [ ] 유튜브 URL을 붙여넣고 3초 안에 재생할 수 있다(네트워크 정상 기준).
- [ ] 0:30–0:40 구간을 지정하면 1배속에서 0:30±0.1초에 반전되고 0:40±0.1초에 원래대로 돌아온다. 0.5배속과 2배속에서도 같은 오차 범위 안에 든다.

**로컬**
- [ ] 파일 앱에서 1GB mp4를 가져오면 진행률이 표시되고, 끝나면 라이브러리에 썸네일/제목/길이가 보인다.
- [ ] webm 등 재생할 수 없는 파일은 가져올 때 거부되고 안내가 나온다.
- [ ] 구간 경계에서 반전 전환이 1프레임 이내로 맞는다(30fps 기준 ≤33ms).
- [ ] ±1프레임 이동이 정확히 한 프레임씩 움직인다.
- [ ] 0.5배속에서 음정이 유지된다.
- [ ] 앱을 갱신(재서명)한 뒤에도 로컬 영상이 남아 있다.

**공통**
- [ ] 전체 반전 ON에서 같은 구간은 원본, 구간 밖은 반전으로 보인다.
- [ ] 구간 안으로 바로 탐색해도 첫 프레임부터 올바른 반전 상태로 보인다.
- [ ] A-B 루프가 10회 이상 연속으로 끊김 없이 반복된다.
- [ ] 앱을 강제 종료하고 다시 실행해도 영상, 구간, 전체 반전, 태그, 메모가 유지된다.
- [ ] 내보낸 JSON을 다른 iPad에서 가져오면 동일하게 재현되고, 충돌 시 선택지가 뜬다. 로컬 항목은 "파일 없음"으로 들어오고, 같은 파일을 연결하면 구간이 그대로 적용된다.
- [ ] Apple TV 화면 미러링 중 TV에 UI 없이 반전 영상만 나오고, iPad 조작이 0.3초 안에 반영된다.
- [ ] 무료 Apple ID로 설치한 앱이 수동 조작 없이 14일 이상 계속 실행된다.

## 11. 가정 및 미결 사항

- **가정**: 전체 반전(baseMirror)은 세션 값이 아니라 영상별로 저장한다.
- **가정**: 태그는 자유 입력이며, 자동완성은 기존 태그로 제공한다.
- **가정**: 로컬 영상은 가져올 때 복사한다(원본 참조 방식은 쓰지 않음). 용량이 두 배로 드는 것은 감수한다.
- **미결**: 유튜브 소스의 외부 디스플레이 모드에서 iPad에 저해상도 미리보기를 둘지 여부(현재는 두지 않음). M5 사용 후 결정한다.
- **미결**: 구간별 재생 속도(예: 어려운 구간만 0.5배속) 기능이 필요한지. 현재는 영상 단위 속도만 제공한다.
- **미결**: 로컬 영상 역재생(AVPlayer가 음수 rate 지원)을 P2로 넣을지 여부.
